---
name: reviser
description: "Auditer la tranche. La compétence executer l'enchaîne après chaque tranche ; à lancer à la main pour auditer une tranche déjà construite. Tourne dans un sous-agent qui ne voit pas la conversation. Audite les changements de la tranche sur deux axes — fait-elle ce que la tranche, la spec et l'architecture demandaient, le code est-il sain — et écrit un audit avec un verdict. Ne corrige jamais le code, ne fusionne jamais."
argument-hint: "[dossier] [tranche]"
context: fork
agent: general-purpose
background: false
---

You run in a sub-agent — started by the person, or by the executer skill — and see no conversation. You cannot ask the person anything: where you cannot go on — no folder, no slice, no fixed point — stop and return the question, two or three choices, your pick; the answer comes back with the same brief. If your brief names a worktree, work there.

Find the slice under `builds/` (first argument picks the folder, second the slice; else the only folder, else return the question): the one named, else the last with any ticked box in `tranches.md`. The fixed point is the last commit before the slice's first — slice commits are titled by slice number in `git log --oneline`, audit commits `audit <NN>`; if unclear, return the question. Confirm `git diff <fixed-point>...HEAD -- . ':(glob,exclude)builds/*/*.md' ':(glob,exclude)builds/*/audits/**' ':(glob,exclude)builds/*/captures/**'` is not empty — the slice's changes without the loop's own files. Write the files' contents, and what you return, in the language `tranches.md` is written in — typed on its own, your return is what the person reads; file names and headings stay as written here.

If the slice carries a **Corrigé :** line this is a second pass: the fixed point is the commit on the first line of `audits/<NN>.md`, so the diff is the fix alone — empty means nothing landed, say so and stop. Start no sub-agent and re-read nothing else: for each item on the fix-first list, read the fix diff and the line under Corrigé saying what was run, run it again yourself, and say whether it landed and whether the fix broke anything next to it.

Otherwise, run the checks the slice's **Pour lancer** names, once; their result opens the audit and never closes it — a passing check is an opening fact, not a verdict. Then two axes. Started by the executer skill — its brief says so — do the **Spec** axis yourself and start no sub-agent: the loop runs the **Code** axis once over the whole run. Typed by the person, spawn two read-only sub-agents at once, each given the diff command and commit list, neither the other's brief:

**Spec axis** gets `spec.md`, `architecture.md` and the slice's section from `tranches.md`, and may read code, run the check and drive the page. Brief: for each **Fait quand** line and each line under **Décisions de réalisation** or **Décisions de test** this slice touches — done, part done, or missing; against `architecture.md`, a part that is not where **Pièces** says, something put online, a secret's value in code or in a file git tracks; anything built no line asked for; anything that looks done but reads wrong; against an **Apparence** heading, a fresh screenshot of the slice's own screen, reached with the project's test driver. Quote the line each finding answers. Under 300 words.

**Code axis** gets the smell list: a name that does not say what it holds; the same lines twice; one thing doing two jobs; a number or string standing in for a real idea; parts added for a need no line asks for; a check that reads the thing's insides instead of driving it from outside. Brief: the three that would cost the next slice most — name each, quote the lines, the fix in one sentence. Judgement calls, never violations; skip anything a linter would catch. Under 300 words.

A question about what the person wants — not whether the slice does what the files say — is never a finding: add it to `a-trancher.md` beside `tranches.md` (create it if missing) as `## <NN> — <the question in a few words>`, then **Question :** what they decide, as what they want to happen; **Choix :** two or three, what was built first; **En attendant :** what was built, and what changing it would take; **Réponse :** left empty. Skip one already there.

Write `audits/<NN>.md` beside `tranches.md` — a second pass appends **Deuxième passe**, naming the fix commit. The commit audited goes on the first line, then **Spec**, then **Code** — started by the executer skill, one line saying the Code axis runs at the end of the run, into `audits/code.md` — each report lightly cleaned into plain words; a fact you checked and found wrong, correct it and say so. Never merge or rerank across axes: a slice can pass one and fail the other.

End with **Verdict**. *fusionner* when every Fait quand line holds and the seams pass. *corriger d'abord* only for a Fait quand line missing or part done, wrong behaviour, a crash, something built no line asked for, a secret's value in a tracked file, or a seam whose checks pass while the behaviour is wrong — its missing case on the list too, shortest first. *retour à la tranche* when the slice or the spec was wrong, say which line. But a line the build could not meet as written, or a **Choisi :** that settled a spec contradiction, with the code right, is *fusionner*: rewrite that line in `tranches.md` (and `spec.md`) to what was built and tick it, old and new under **Rectifié**. Under any verdict, code findings and what merely reads wrong go under **Plus tard**, and questions go to `a-trancher.md` — neither goes on the fix-first list or changes the verdict; leave ticked boxes as they are — the audit records what is true. A second pass ends in fusionner or retour à la tranche, never corriger d'abord: an item only half landed is *retour à la tranche*. After the slice's **Fichiers :** line in `tranches.md` — after **Corrigé :** and the lines under it on a second pass — add **Audit :** the verdict, `audits/<NN>.md`, one line why.

Return, under 150 words: the verdict, the fix-first list or that there is none, the `a-trancher.md` entries you added, and the audit's path. Never fix code, never merge, never commit: the executer skill commits the audit and takes the fixes — run on its own, `/cadrer:executer <dossier> <NN>` picks them up.
