Vérifie ce que la personne devait préparer avant la livraison, montre ce qui va être créé, payé ou envoyé et attend son accord, met en ligne, refait le trajet sur la vraie adresse et écrit `livraison.md`. Ne corrige jamais le code."

You put the finished build where `architecture.md` says it runs, with the person here: this step creates, spends and sends real things, and nothing that cannot be taken back happens without their yes. Read `builds/<NN>-<slug>/architecture.md` first (a number or name given as argument picks the folder, else the only one, else ask) — **Pièces**, **Comptes et secrets**, **Données**, **Coût** and **À faire à la main** are rules — then `tranches.md`, `a-trancher.md`, `audits/code.md`, and `livraison.md` if an earlier run wrote it. No `architecture.md`: say the affiner step writes where it runs, and stop. Answer, and write the files' contents, in the person's language; file names and headings stay as written here. Put questions to the person through the AskUserQuestion tool when you have it: your pick as the first option, the context it needs in your message just before.

**Ready.** Check, and say what does not hold: every slice's **Audit :** line says *fusionner*; every `a-trancher.md` entry has a **Réponse :**, and each answer that changes what gets built carries its `→ <NN>` to a slice that is *fusionner*; the working tree is clean; every **Pour lancer** check passes once more, here, without touching what the person already keeps — their data stays as it was. A slice not *fusionner*: stop and name `/cadrer:executer`. An answer not yet placed: stop and name the repartir skill. An empty Réponse: put it to them now, the way executer does, and commit `a-trancher.md`; an answer that changes the build stops here too. Note the commit you ship.

**Chores.** Put every unticked *avant la livraison* item under **À faire à la main** to the person in one message, in order — what to do, where, why it is needed. A secret's value never passes through this conversation — and a command typed here with `! ` lands in it, with what it prints: give them the page where they paste the value, or the command to run in a terminal of their own outside this window, into the place **Comptes et secrets** names. `! ` only for a command with no value in it and none in what it prints, such as a login that opens a browser. Wait until they say done. Then check each one you can from here without showing a value — the account lets you in, the address answers, a secret exists by name (list names, never print values), a value is no longer its local stand-in from **En local** (compare, never display) — and tick it; commit `architecture.md` as `À faire à la main : <what was checked>`. One that fails: say what you saw, and go no further until it passes or they cut it; cutting one that a part needs cuts that part, say what the people using it lose.

**Plan.** Before anything leaves this computer, show one table, in order: the action · what it creates, changes, sends or deletes out there · what it costs now and per month · how to undo it. Real data starts empty or from what the person gives, never from local test data; a later run changes stored data only through a row that says how to get it back. The cost alert **Coût** names is a row, and so is turning on the copies **Données** relies on. The last row is the check online. Wait for their yes; a row that changes is shown again. A row that spends money gets its own yes, with the amount. A no, or not now: stop there, say what is ready and what the next `/cadrer:livrer` starts from; write no `livraison.md`.

**Go online.** Run the plan in order from the commit you noted, one line per result. Never write a secret's value into code, a commit, a file git tracks, or a command whose output is shown. A row that fails: stop, say what you saw, and undo the rows already run only if they say so. Either way, before ending write `livraison.md` as below with what is out there now — each row run and what it created, spent or sent, each row undone — the failed row and what stopped it under **Reste à faire**, and commit it as `livraison — arrêtée : <row>`; the next run reads it and repeats no row that already ran. Never fix code here: what needs a code change goes under **Reste à faire**.

**Check online.** On the real address, follow the **Trajet** from `architecture.md` as the person would, then each **Fait quand** line that can be seen from outside — through a browser tool when you have one, with the person's own address or account for anything sent, never someone else's. What you cannot see from here — a message in their inbox, a notification on their phone: ask them to look, and write what they said. Screenshot each screen reached into `builds/<NN>-<slug>/captures/livraison-<state>.png` and look at each yourself. Remove what the check created, the way the plan said. Something wrong online that was right locally: say it plainly, and offer to go back to what was online before (the plan's undo) or leave it up — their choice.

**Write** `livraison.md` beside `tranches.md` — a later run puts its section on top, under the date — with exactly these headings: **En ligne** — the address, the date, the commit, the slices it holds; **Mise en ligne** — the commands in order to do it again, secrets by name only; **Vérifié en ligne** — each Trajet step and Fait quand line checked: seen, or what was seen instead, with its screenshot; **Si ça casse** — how to go back to the previous version, how to get the data back the way **Données** says, where to look when it stops; **Reste à faire** — every À faire à la main item still open, and each thing found wrong online as one line the repartir skill can turn into a slice. Tick the chores done in `architecture.md`. Commit `livraison.md`, `architecture.md` and the captures as `livraison — <address>`.

End with: the address; what was checked and what was seen; what is wrong online, if anything, and what comes next — the repartir skill on **Reste à faire**, `/cadrer:executer`, then `/cadrer:livrer` again; in plain words, the first thing to do now.

Run again after new slices: chores not yet ticked only, a plan showing what changes from what is online, a check covering the Trajet and the new slices' lines. Never merge, never push to a shared branch unless a plan row says that push is how it goes online, never change a verdict.
